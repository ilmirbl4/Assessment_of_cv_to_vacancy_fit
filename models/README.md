# Модели и эталонные артефакты

Каталог `models/` — единственное место для нейросетевых артефактов приложения. Соседние
проекты, кэш Hugging Face и хостовое Python-окружение не используются. Веса не входят в Git:
в репозитории хранятся `manifest.json`, этот файл и скрипт проверки. На сервер артефакты
доставляются отдельным архивом (`deploy/package-artifacts.sh`).

## Состав

| Каталог | Назначение | Происхождение |
|---|---|---|
| `USER-bge-m3/` | би-энкодер вакансий и резюме, 1024 измерения, CLS + L2 | `deepvk/USER-bge-m3`, ревизия `0cc6cfe48e260fb0474c753087a69369e88709ae` |
| `rubert-mini-frida-ner/` | NER требований и навыков, BIO, шесть типов | локальный экспорт `checkpoint-1690`; публичной ревизии нет |
| `mmarco-mMiniLMv2-L12-H384-v1/` | кросс-энкодер пар «требование — фрагмент» | `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`, ревизия `1427fd652930e4ba29e8149678df786c240d8825` |

Скачиваемые файлы, их SHA-256 и ревизии зафиксированы в `manifest.json`. При старте приложение
сверяет контрольные суммы; `HF_HUB_OFFLINE=1` и `TRANSFORMERS_OFFLINE=1` запрещают незаметную
загрузку другой ревизии. `config.json` участвует в fingerprint модели, эксплуатационные
`ML_BATCH_SIZE`, `ML_TORCH_THREADS` и пути каталогов — нет. Полный список семантических
параметров указан в `backend/app/ml/artifacts.py`.

## Доставка на чистый сервер

1. На машине с доставленными артефактами выполните `sh deploy/package-artifacts.sh`.
   Скрипт проверит локальные hashes и создаст `data/artifacts/runtime-artifacts.tar.gz`
   (публичные модели + эталон) и `data/artifacts/private-ner.tar.gz` (обученная NER).
2. Перенесите архивы и `SHA256SUMS` на сервер, распакуйте в корень проекта:
   `tar -xzf runtime-artifacts.tar.gz`, `tar -xzf private-ner.tar.gz`.
3. Проверьте `cd backend && python3 -m scripts.download_models --verify`.
   Backend в контейнере работает от UID 10001: выдайте весам права на чтение
   (`chmod -R a+rX models`), иначе старт завершится `PermissionError` на `model.safetensors`.
4. Для публичных моделей без готового архива допустима загрузка только закреплённых файлов:
   `python3 -m scripts.download_models` (без `--verify`). Для приватной NER загрузки из
   интернета нет: нужен архив с машины обучения. Чистый checkout без него завершится понятной
   ошибкой с именем отсутствующего файла.

## Эталон вакансий

`data/reference/` содержит 20 000 неизменяемых вакансий успешного запуска
`8b001c18-dd71-4128-bf37-82e8f009f08e`, манифест происхождения и кэш признаков.
`reference_id=trudvsem-20000-66d729a0f8051cbb`, снимок `2026-10-19T19:26:44Z`.
Файлы `*.jsonl.gz` и `*.jsonl` большие и не входят в Git; манифест — входит.
Эталон монтируется в контейнер только для чтения и не заменяется текущим сбором.

## Ограничения качества

Готовый кросс-энкодер обучен релевантности, а не трём статусам выполнения требований.
Предварительная ручная проверка находится в [docs/models/calibration.md](../docs/models/calibration.md):
на коротких русских требованиях модель плохо разделяет выполненные и невыполненные пары.
Пороги `ML_PARTIAL_THRESHOLD` / `ML_COVERED_THRESHOLD` не откалиброваны для промышленного
качества; для итоговой системы нужно дообучение на размеченных парах. NER обучена на вакансиях;
перенос на резюме даёт лишние сущности из строк опыта и требует отдельной проверки/дообучения.
