# Отчёт по веб-клиенту

Дата: 18.11.2026. Клиент — React 19 + Vite + TypeScript, маршрутизация React Router,
серверное состояние TanStack Query, формы React Hook Form + Zod, стили Tailwind.

## Состав

- Публичные страницы: вход, регистрация, подтверждение почты, восстановление пароля,
  согласие, 403/404.
- Кабинет соискателя: резюме (PDF/DOCX, замена, удаление, статус embedding), подбор с фильтрами,
  карточка вакансии с тремя статусами и цитатой, избранное, удаление аккаунта.
- Админка: сбор данных, скорость подбора, дрейф данных с разделами «Входные данные»,
  «Выходы модели», «Отклик пользователей».
- Готовые состояния: скелетоны, ошибки сети/сервера, пустая выдача, недоступные метрики
  с причиной, баннер подготовки системы.

## Контракты

`src/api/types.ts` и `src/api/endpoints.ts` соответствуют OpenAPI backend. Ответы админки
типизированы, отсутствующие метрики — `null` со статусом, а не `0`. Ошибки приводятся
к `ApiError` с кодом/полями; 401 централизованно очищает кэш и ведёт на вход.

## Моки и тесты

- `src/mocks/**` — MSW-двойники для unit/e2e; production-сборка их не содержит
  (`main.tsx` подключает моки только при `import.meta.env.DEV && VITE_USE_MOCKS=true`).
- Unit: Vitest + Testing Library, 11 файлов / 111 тестов.
- E2E: Playwright в Chromium/Firefox на локальном dev-сервере с MSW; это проверка
  интерфейса, а не сквозной сценарий с настоящим API. Сквозной API-сценарий проверяется
  backend-интеграционным тестом `backend/tests/test_user_scenario.py`.
- Скриншоты генерируются командой `npm run screens` в `docs/screens/` и не входят в Git.

## Проверки

```text
npm run typecheck   → 0
npm run lint        → 0
npm test            → 11 files, 111 tests passed
npm run build       → 0; MSW-чанк в dist отсутствует
```

Проверка production-сборки: чанк `browser-*.js` (MSW) больше не создаётся; крупные
библиотеки вынесены в отдельные vendor-чанки.

## Ограничения

- E2E с настоящим API/SMTP и реальными моделями вынесен в отдельную задачу: для него нужны
  поднятый Compose-стек, тестовый почтовый ящик и доставленные артефакты.
- Публичный HTTPS/Caddy проверяется на сервере с реальным доменом; в клиенте учтены
  относительные ссылки `/api/v1`, secure-cookie и forwarded-proto.
